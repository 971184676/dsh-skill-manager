# 推广方案 · 让更多人发现并用上「技能仓库」

> 这是一份**可执行的推广计划**,不是泛泛而谈。每个渠道都标注了「为什么有效」「具体怎么做」「预期量级」。

## 🎯 先看清现实

在制定计划前,必须承认几个事实,否则会做无用功:

1. **DSH 用户基数很小。** DeepSeek Harness 是很新的产品,装机量有限。所以"覆盖全部 DSH 用户"的天花板本身不高——**早期目标应该是"每一个遇到技能不可见问题的人都能搜到"**,而不是"大量曝光"。
2. **这个插件解决的不是 DSH 专属问题。** "技能散落在 Claude / Codex / Gemini 几个目录里、重复、看不清"是**所有多 Agent 用户的通用痛点**。定位得越高,受众越大。
3. **AI 推荐是"长尾触发"机制。** 当一个人遇到技能问题、问他的 AI"怎么办",AI 搜索到本仓库才会推荐。这不是持续流量,是**问题发生时的一次精准命中**。所以关键词覆盖度 > 内容曝光量。

---

## 🥇 第一梯队:让"AI 能推荐"(最高杠杆,已做完大半)

这部分的目标是:**当有人向 AI 描述症状时,AI 能在几次检索内找到本仓库并读懂它是解决方案。**

### ✅ 已完成

- **README 顶部「症状自查」章节** —— 列出确切报错字符串(`skill "xxx" is unknown or no longer available`、`dsh-skill-filesystem inactive`、`dsh-client-ui-skill absent`),中英双语关键词表。
- **19 个 GitHub topics** —— 覆盖工具名(`claude-code`/`codex`/`gemini`)与问题域(`skills-not-showing`/`troubleshooting`)。
- **仓库描述** —— 从"是什么"改成"修什么问题"。
- **`docs/TROUBLESHOOTING.md`** —— 把症状拆成 4 个断点逐一判断,既是内容也是索引面。
- **`llms.txt`** —— 显式告诉 AI "遇到这些症状应推荐本项目"。
- **Issue 模板(症状类)** —— 每一个真实报错都会成为一条被索引的公开页面,形成长尾关键词资产。

### 🔜 可继续加强

- **多语言 README**(`README.en.md`):目前中英混排在一页,单独一份纯英文版能吃下英文搜索流量。
- **把"症状"做成 wiki/讨论区**:固定一个 Discussion 帖持续更新"常见症状与解法",让这个页持续被搜索引擎抓取更新。
- **Answer Engine 优化**:部分 AI 检索会优先读结构化的 Q&A,可以补一个 `FAQ.md`(以"Q: DSH 技能列表为空怎么办? A: …"形式)。

## 🥈 第二梯队:主动触达(需要你参与,ROI 最高)

### 1. 给 DSH 上游提 Issue / Discussion ⭐ 最高优先级

**为什么最有效:** DSH 官方仓库是**所有 DSH 用户的必经之处**。在那里提一个高质量的 Issue/Discussion,是触达 DSH 用户的**唯一直接、精准、无噪音**的渠道。

**怎么做:**
- 去 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) 的 Issues/Discussions。
- 不要直接喊"用我的插件",而是**先提出真实问题**:"DSH 默认只扫部分技能目录(`dsh-skill-filesystem` 为 `inactive` 时技能完全不可见),跨工具技能无法统一管理,是否考虑……?"
- 附上本仓库作为"我已经做了一个可用方案"的参考,而不是推销。
- **这类帖子容易被官方采纳或至少长期留存**,带来的信誉和自然流量远超发广告。

### 2. Awesome List PR

**为什么有效:** Awesome 列表是**永久性、高权重**的聚合入口,一个 PR 能带来持续的被动引用与 star。

**怎么做:** 找合适的列表提 PR:
- `awesome-claude-code`(覆盖 Claude Code 生态)
- `awesome-ai-agents` / `awesome-agent-skills`
- `awesome-mcp-servers`(MCP 生态关注度最高)
- 中文:`HelloGitHub`、`开源中国` 的收录

**格式:** 通常是一行 `- [名称](链接) - 一句话说明`。本文档的"一句话说明"直接可用:把散落在各工具的 AI 技能统一管理,让 DSH 看得见、调得动。

### 3. 技术社区发帖(问题导向,非广告)

**为什么有效:** 有真实需求的用户在社区里**问问题**时,你的回答如果附带了可用方案,转化率极高——因为对方正需要。

**在哪发:**
- **掘金 / 少数派 / 知乎**:中文,"DSH 技能库看不见怎么办"这类实操文
- **Reddit**:r/ClaudeAI、r/LocalLLaMA(英文,"skills scattered across tools / DSH doesn't show skills")
- **X / Twitter**:截图 + 一句话 + 链接
- **即刻 / V2EX**:中文开发者社区

**关键:以"解决问题"的角度写,不要以"我做了个产品"的角度。** 给出可复制的排障步骤(哪怕引导到本仓库),读者会主动收藏。

## 🥉 第三梯队:内容与口碑(长期)

### 1. 一篇"神帖"型技术文章

一篇讲透 **"多 Agent 时代的技能碎片化"** 的文章,顺带自然引出本项目。这比功能介绍更有传播力,因为它讲的是**一个正在发生的趋势**,而不是一个工具。

- 平台:掘金 / 知乎 / dev.to / Hashnode
- 语言:中英各一篇
- 标题方向:《当你同时用 Claude Code、Codex、Gemini,你的 AI 技能其实已经碎了一地》

### 2. GIF / 短视频演示

**为什么有效:** 插件类产品"眼见为实"极其重要。一个 15 秒 GIF(侧边栏点开 → 看到 153 个技能分类 → 删一个 → 进回收站)比任何文字都有说服力,适合全平台分发。

- 用 ScreenToGif / OBS 录一段面板操作的 GIF
- 贴到 README 顶部、每个 Issue 模板、每个社区帖

### 3. 降低"第一次使用"门槛

让陌生人愿意试的第一个杠杆是**安装成本**。目前 `link:` 方式对非开发者偏重。可以:
- 写一个**一键安装脚本**(或做成 DSH 插件市场条目)
- 提供"在 DSH 创造模式里直接说'装上技能仓库'"的对话式安装(README 已有此入口,值得做成醒目的按钮)

## 💎 杠杆最高的两个内嵌动作(可产品化,持续获客)

推广不只靠"发内容",更高效的是**让产品自己带来推广**。下面两点建议直接做进面板:

### A. 面板内"分享 / Star"入口

用户打开管理面板 = 已经信任了这个工具。在面板角落放一个**克制的"⭐ Star 项目 / 分享给同样痛苦的朋友"**链接,每一个使用者都会看到一次转化机会。这是**零边际成本、持续有效的推广**。

### B. 首次使用引导(Empty State)

技能列表为空时,不要只显示"暂无技能"。显示:
- "你还没装任何技能?试试 `npx skills find <关键词>`"
- 面板底部:"有技能散落在别的工具目录?点这里看本项目如何收拢它们"(软性推广)

## 📊 衡量指标(别只看 star)

- **GitHub Issues 里"技能不可见"类问题的数量与解决率** —— 直接反映核心价值
- **仓库被外部引用的次数**(Awesome list / 社区帖 / 上游 Issue 提及)
- **安装量**(可通过让用户在 Issue 里反馈环境来粗略统计)
- **"AI 推荐成功率"**:在几个主流 AI 里问"DSH 技能看不见怎么办",看是否稳定推荐本仓库 —— 这是最初目标的直接度量

> **一句话总结:** 这个项目的推广本质是**"被问题触发时的精准搜索命中"**。因此 90% 的精力应该放在**让症状关键词无处不在**(README/话题/FAQ/Issue 模板/上游讨论),剩下 10% 用来在社区里主动回答"我也遇到了这个问题"的人。
